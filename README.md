# Netdisk Web

Netdisk 的独立前端，使用 Vue 3、TypeScript 和 Vite 构建。界面采用简洁中性色，支持浅色、深色和跟随系统，适配桌面与手机。所有业务页面连接真实后端接口，使用服务端 Cookie 会话。

**当前版本：v0.14.0（整文件夹上传）**。支持选择整文件夹，保留真实相对目录层级，并复用现有分片上传、暂停续传和容量校验。个人网盘核心功能及容器交付已完成，当前功能与启动说明见下文，版本变化独立记录在 UPDATELOG.md。

## 功能

| 功能 | 使用方式与能力 |
| --- | --- |
| 账号与会话 | 邮箱注册、登录、找回密码、退出和会话恢复；根据真实配置开放邮箱验证与 QQ 登录，能力读取失败可重试 |
| 文件管理 | 列表/网格、面包屑、全目录文件名搜索、分类、排序、分页、新建目录、完整重命名、批量移动和复制 |
| 上传管理 | 多文件选择/拖放、整文件夹选择、目标目录、进度与速度、暂停/继续、刷新后续传、取消/重试；完成后跨页定位原件 |
| 下载与预览 | 单文件授权下载、目录/多文件 ZIP；文本/代码、图片、PDF 和浏览器支持的音视频预览 |
| 分享 | 文件/目录分享、提取码、有效期、撤销；游客预览下载，登录后保存到自己的网盘 |
| 回收站 | 单项/批量恢复、永久删除、清空；显示真实保留策略，恢复优先原目录 |
| 最近文件 | 按更新时间汇集本人文件，分页查看；核对目录链和实际页码后定位 |
| 个人设置 | 修改昵称、上传头像、修改密码；成功改密后旧登录会话失效 |
| 管理控制台 | 用户筛选/禁用/配额、按所属用户管理文件、邮件模板与新用户初始容量 |
| 界面与导航 | 明暗/系统主题、偏好保存、桌面侧栏、手机抽屉、键盘操作及加载/错误/重试反馈 |

管理入口仅向管理员显示，直接访问管理地址也会重新核对角色；后端独立执行权限检查。文件数量、容量、身份与操作结果均取自接口，只有服务器确认后才更新完成状态。

## 本地开发

需要 **Node.js 22.13 或更高版本**，并准备好配套后端及其 MySQL、Redis 和文件存储。

```sh
npm ci
npm run dev
```

默认访问 `http://127.0.0.1:5173`。复制 `.env.example` 为 `.env.local` 可设置开发代理，默认后端为 `http://127.0.0.1:7090/api`。保留代理的 `changeOrigin: false`，让后端能够检查同源写请求。不要将真实凭据放入前端环境变量或提交到仓库。

前端请求以 `/api` 为默认前缀；生产环境通过 HTTPS 将密码交给后端校验，不在前端做 MD5，也不保存密码或会话令牌。后端数据库初始化、环境变量和管理员配置见 [部署说明](https://github.com/Enderherman/Netdisk/blob/master/docs/DEPLOYMENT.md)。

```sh
npm run build
npm run preview
```

构建产物位于 `dist/`。`preview` 用于检查静态构建，不能代替生产环境的 API 反向代理。

## 常用操作

在“我的文件”中进入目录后，可新建文件夹或上传；分类和搜索会查询全部目录。名称支持中文和空格，但不能包含路径分隔符、控制字符、首尾空白或跨平台保留名称。重命名需要输入完整文件名，修改扩展名不会转换文件格式。

选择文件或目录后可以移动、复制、分享、打包或移入回收站。移动与复制由后端校验目标、循环目录及重名。目录和多文件使用 ZIP 下载，保留中文名称和空目录；开始下载的提示只表示请求已交给浏览器，最终结果以下载列表为准。

“移入回收站”可以恢复；永久删除与清空需要确认，清空作用于回收站全部页面。原目录不可用时，恢复项目回到全部文件。详情见 [批量操作](docs/BULK-OPERATIONS.md)、[分享](docs/SHARING.md) 和 [回收站](docs/RECYCLE.md)。

## 上传与续传

“选择文件夹”会先创建或复用目录，再逐文件加入现有队列；目录准备可停止和重试。一次最多1000个文件、500个目录、16层，空目录因浏览器选择能力限制需手动新建。目录拖放会明确提示改用文件夹选择，不会错误上传为零字节文件。

从文件页发起上传会使用当前目录，也可在上传管理中更换位置。前端以 4 MiB 块计算全文件 MD5，再以 8 MiB 分片逐个发送；实际文件上限还受账户容量与后端限制。

暂停会中止本页传输，已接受的分片仍占临时空间；取消需服务器确认，已经完成的原件不会被取消操作删除。首片断网且未取得任务 ID 时，应刷新服务器任务列表确认状态，不会盲目重建上传。

关闭或刷新页面后，需要重新选择原文件。前端会核对摘要、名称、大小、目录与分片边界，只发送服务器缺失的部分。退出、会话失效或账号切换会中止旧账号上传。任务完成后的“查看文件”先读取最新资料，再核对真实条目与实际页码；定位可取消，失败提供按名称搜索的入口。完整说明见 [上传与续传](docs/UPLOADS.md) 和 [最近文件](docs/RECENT.md)。

## 预览范围

| 类型 | 当前边界 |
| --- | --- |
| 文本与代码 | 以 UTF-8 读取前 64 KiB，超出部分明确提示截断 |
| 图片 | 最多 20 MiB，核对实际内容类型 |
| PDF | 最多 100 MiB，由本地 Worker 解析并绘制画布，支持分页和缩放 |
| 音视频 | 使用浏览器原生控件与 Range，取决于浏览器支持的编码 |
| HTML、SVG、Office、压缩包等 | HTML/SVG 不执行；按类型显示源文本或提供下载降级，不把私有文件传给第三方转换服务 |

加密 PDF、超限文档和不支持的媒体格式可下载后查看。详细限制、授权地址和资源清理规则见 [预览说明](docs/PREVIEW.md)。

## 自部署

项目提供 Node/Nginx 多阶段 Docker 镜像。运行容器采用非 root 用户，配置同源 `/api` 代理、SPA 深链回退、PDF Worker MIME，以及上传/下载流式传输。生产访问应使用 HTTPS。

MySQL、Redis、后端和前端的完整 Compose 配置、初始化/迁移、持久化、反向代理和一致备份步骤统一维护在后端 [Docker 自部署说明](https://github.com/Enderherman/Netdisk/blob/master/docs/DEPLOYMENT.md)。

前端已通过 [真实 Docker 构建与 Nginx 验证 CI](https://github.com/Enderherman/NetdiskWeb/actions/runs/37226760993)，配套后端也已通过 [Docker 交付验证 CI](https://github.com/Enderherman/Netdisk/actions/runs/37227282709)。这些结果覆盖对应工作流中的镜像和容器检查，不等于完整 Compose 或目标 NAS 的业务验收。**本轮没有部署到 NAS。**

## 外部服务与范围边界

邮箱注册和找回密码需要后端配置可用邮件服务。已有真实流程经过本地 SMTPS 捕获，尚未证明外部邮箱送达；正式使用前仍需核对收件箱、服务商限制和完整注册/找回流程。

QQ 登录默认关闭，需配置并审核真实 QQ 开放平台应用，回调与前端保持同源。能力接口明确关闭时显示不可用，读取失败则提供重试。QQ 登录创建独立账号，不按同名资料自动合并邮箱账号；本轮没有真实 QQ 应用凭据或外部授权验收。见 [QQ 登录](docs/QQ-LOGIN.md)。

当前范围不包含Office 在线转换、自动视频转码、全文内容检索、协作编辑、商业会员/支付、桌面同步或多机部署。现有后端没有共享 HTTP Session 与跨主机文件锁，不能只增加副本数就宣称支持多实例。
