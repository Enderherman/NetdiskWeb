# 上传中心与文件夹导入

验收日期：2026-10-05。

## 使用

1. 在文件页选择“上传文件”，或进入侧栏“上传管理”。确认保存位置。
2. 选择或拖入多个文件。前端校验原文件后逐个上传，切换应用内页面不会停止队列。
3. 可暂停、继续或重试。暂停后服务端可能已接受当前片，继续时会先查询状态，不凭本地计数猜测。
4. 取消需确认，成功后服务端清理临时分片。已完成原件不属于可取消的临时数据。
5. 刷新页面后，在“服务器任务”重新选择同一原文件。已确认分片不会重复传输。
6. 已完成任务可查看原件。任务记录保留原上传名称，现名不同时会单独显示；查看入口优先跟随原件当前所在目录。

## 整文件夹导入

使用“选择文件夹”保留浏览器提供的真实相对路径。普通拖放仍只接收文件：拖入目录或目录/文件混合时整批拒绝，并提示改用文件夹选择，避免将目录误传成零字节文件。真正的零字节普通文件仍支持上传。

导入先完整校验选区，再按层级查询当前账号目标目录，创建或复用同名文件夹，最终把每个文件按服务器返回的真实父目录 ID 加入既有分片队列。不同合法根会分别保留；同一目录只准备一次。目录被同名普通文件占用时停止，不覆盖该文件。重复文件路径、大小写/重音冲突、路径穿越、非法名称、缺失相对路径及名称不一致都会在写入前拒绝。

每次最多 1000 个文件、500 个目录、16 层（含选中的根目录）。单个目标目录最多查询 10000 项，全任务最多累计读取 20000 项、执行 2000 次准备请求；超过时需选择更具体的目标或分批导入，避免缓存和请求量随目录数量无限增长。

目录准备有独立进度、停止和原位置重试。全部准备完成前不会把任何文件加入上传；“已加入上传队列”也不代表文件已上传成功，完成状态仍以原队列收到的服务器回执为准。

停止、离开上传页或账号变化会取消后续准备。已创建的目录保留，网络中断时最后一个创建请求可能已经完成，不能把客户端取消说成数据库回滚。重试会重新读取并复用真实目录；账号变化会清除原选区，不会把旧账号的 File 自动加入新账号队列。离开页面后已加入的普通上传仍按原队列规则继续。

浏览器 `webkitdirectory` 不返回空目录，因此空目录不能由此选择器恢复，需要手动新建。此功能不使用文件路径作为服务器磁盘路径，也没有自动删除目录的回滚操作。

2026-10-05 已真实验收：包含中文嵌套、两处同名但不同内容、零字节文件的夹具，首次创建 4 个目录、上传 5 个文件；整目录 ZIP 下载后，5 个文件的字节和 SHA-256 均与原夹具一致。再次导入创建 0 个目录、复用 4 个目录，5 个副本均以秒传完成并自动使用 `(1)` 名称，原目录和原件保留。空目录未出现，与界面提示一致。

## 完成与异常

- `uploading` 不是上传成功，即使是最后编号的分片，也必须等待服务端完成回执。
- `upload_finish` 或 `upload_seconds` 才会显示完成。100% 的传输事件本身不代表数据库提交或 MD5 校验完成。
- 首片超时/断网可能留下服务器任务而没有返回 ID。此时禁止直接重新创建，请刷新服务器任务列表处理。
- 原件已回收、任务取消或过期不能通过旧 ID 复活。
- 名称、目标目录、整文件摘要、已知文件大小或分片边界不匹配会拒绝续传。
- 服务端上传中不提供声明总大小，因此浏览器按账号保存已知大小和分片大小；缺少本地记录时仅可从已接受的分片推断边界，并始终校验全文件 MD5。没有足够证据时要求取消后重传。

## 资源与身份

摘要采用 `hash-wasm` 的 MD5 实现，Worker 每次只读取 4 MiB；上传每次 8 MiB、最多 10000 片，空文件使用一片。浏览器原生 File/Blob 切片避免整文件内存拷贝，摘要工作不阻塞主线程。

开发环境在 Vite 启动时显式预构建 `hash-wasm`。Worker 依赖如果等到首次选择文件才被发现，Vite 可能重新预构建并刷新整页，导致本地待传队列丢失；预热把这一步移到上传之前。更新配置后应重启开发服务再进行首次上传验收。生产构建已包含独立摘要 Worker，不依赖运行时预构建。

冷启动首传已复核：118 B 文本、20 MiB 文件与零字节文件一次选择后全部完成，队列保留三个任务，未再因首次 Worker 预构建刷新页面。

页面只保存恢复元数据，不保存文件内容、密码或会话凭据。恢复键以当前 userId 和服务器 fileId 隔离。账号变化立即中止旧上传请求和摘要 Worker，清空 File 引用；后续响应不能污染新账号。

接口和按钮区分本次本地队列与服务器任务，服务器临时占用以接口实际值显示；取消未确认时不把临时占用显示为释放。完成后重新获取账户空间，不自行累加估算容量。

## 测试范围

自动测试验证增量 MD5、分片参数、XHR 中止、状态回执、续传边界、取消、身份变化、旧响应隔离及上传界面；完成链接覆盖自动重名、用户改名、移动目录与旧后端兼容。

真实浏览器与 MySQL/Redis 已验证 20 MiB 三片上传、零字节上传、128 MiB 暂停后继续、192 MiB 刷新后重选原文件续传、错误原文件拒绝、配额不足及确认取消。完成文件长度、MD5 与 SHA-256 与本地原件一致，取消后临时目录只剩 manifest/lock，不再保留数据分片。

`actualFileName` 与 `navigationPath` 是后端可选定位字段。“查看文件”先重新读取最新任务，用当前名称查询候选并按文件 ID 核对真实条目，再复用最近文件的有界父链和分页查找。跳转时带上实际页码、每页 100 项、更新时间降序和文件 ID，进入目录后选中并聚焦原件；目录优先造成的分页偏移也会计入。

定位允许取消，最多等待 30 秒；候选搜索最多 100 页，父链最多 100 层，实际目录查找最多 100 页。文件已移动、改名、回收、路径异常或超出查找范围时明确提示，并提供按最新已知名称搜索的入口，不会只跳到第一页冒充定位。退出或账号切换会中止定位，旧响应不再跳转。

旧后端缺少两个定位字段时保留原任务名称搜索兼容，不将上传时的 `filePid` 当作当前目录。此操作不改变固定上传元数据和续传校验。
