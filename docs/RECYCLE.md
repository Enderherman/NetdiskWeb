# 回收站前端模块

模块文件仅位于 `src/features/recycle/`，独立使用真实 `/recycle` 接口，依赖后端 `v0.5.0` 的策略与清空契约。未修改路由、侧栏、应用外壳、文件页、依赖或版本文件。

## 接线

1. 在根路由注册 `/recycle`，组件使用 `features/recycle/RecycleView.vue`，标题“回收站”，保持为需要登录的普通页面，不设置 `meta.public`。
2. 将侧栏回收站入口接到 `/recycle`，由已有 `AppShell` 提供布局和主题。
3. 更新文件页中“回收站恢复入口将在后续版本开放”的旧文案，可提供前往回收站的链接。保留原来的移入回收站接口与成功后容量刷新行为。
4. 接线后由根应用完成浏览器验证，包括暗色/亮色、手机布局、键盘确认、恢复后到文件页查找、跨页清空与 901 跳转。

## 界面与操作

`RecycleView` 复用现有 `FileCollection` 网格与 `ModalDialog`。在卡片下方单独显示回收时间和保留情况，没有把 `recoveryTime` 写入 `lastUpdateTime` 冒充原修改时间。点击文件/目录仅打开回收项详情，不尝试预览已回收内容。

- 列表按真实分页响应显示。全选仅选择当前页，换页成功后清空旧页选择。总数仍大于 0 而当前页为空时，提示当前页暂无内容，不宣称整个回收站为空。
- 恢复确认明确说明：优先回原目录，原目录不可用时回到“全部文件”，同名自动加序号；同批父子条目的恢复层级由后端决定。成功提示不猜测实际恢复后的路径。
- 永久删除必须再次确认所选范围并勾选不可恢复提示。取消确认不发送请求；只提交明确选择的 ID，不隐含选择其他页面。
- 清空是独立操作，确认窗口明确覆盖当前账号的所有页面、所有回收项和回收子树，与当前选择无关。调用 `/recycle/clear` 时不发送 `fileIds` 或 `userId`。
- 清空数量来自 `deletedCount`，包含后端实际处理的文件/文件夹记录。返回 0 时显示“回收站已为空”，不编造删除数量。
- 恢复、永久删除、清空均在接口成功后刷新列表、当前策略和真实使用空间。失败保留选择与确认窗口，可重试；901 不显示成功、不伪造空列表、不刷新出猜测的空间值。根应用已有的登录失效处理仍生效。
- 写操作进行中禁止重复提交、关闭确认和分页。账户状态切换时取消旧确认、清除旧数据，迟到请求不会展示前一个账户的内容。

## 真实策略与日期

`GET /recycle/policy` 返回 `retentionDays`、`autoCleanupEnabled`、`restoreStrategy: original_or_root`。组件独立加载策略，失败时保留未知状态并提供重试，绝不回退到写死的 30 天。

- 自动清理开启时显示实际配置天数，并根据条目的 `recoveryTime` 计算保留截止时刻。
- `retentionDays=0` 或全局自动清理关闭时，以 `autoCleanupEnabled` 为准显示当前关闭，不把条目描述为永久保留。
- `recoveryTime` 按后端 `yyyy-MM-dd HH:mm:ss / GMT+8` 严格解析和显示，不使用浏览器本地时区猜测。无回收时间、非法日期或过大日期不会生成虚构的截止日或剩余天数。
- 等于或超过截止时刻只显示“已达到保留期限，等待服务器清理”。是否仍在回收站以及能否恢复，继续以真实列表和操作响应为准。

## API

| 功能 | 方法与参数 |
| --- | --- |
| 列表 | `GET /api/recycle/loadRecycleList?pageNo=&pageSize=`，页面提供 20/50/100。 |
| 策略 | `GET /api/recycle/policy`。 |
| 恢复选中 | `POST /api/recycle/recoverFile`，表单 `fileIds` 逗号分隔。 |
| 永久删除选中 | `POST /api/recycle/delFile`，表单 `fileIds` 逗号分隔。 |
| 清空全部 | `POST /api/recycle/clear`，空表单；响应 `data.deletedCount`。 |

使用已有 `api/client.ts` 的 Cookie 会话与业务码判断。清空响应不完整时提示刷新核对，不当作成功。容量显示通过 `useAccount().refreshSpace()` 读取后端，不在前端按文件列表自行加减，也不承诺物理磁盘立即释放。
